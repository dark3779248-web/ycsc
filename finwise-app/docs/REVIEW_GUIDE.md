# 审核指南

## 1. 每次审核先看什么

1. GitHub `main` 最新提交说明。
2. `docs/CHANGELOG.md` 中的改动原因与影响。
3. `src/` 的界面或业务变化。
4. `supabase/migrations/` 是否有数据库变化。
5. Vercel 构建是否为 `Ready`。

## 2. 本地文件审核

| 范围 | 主要文件 | 审核重点 |
|---|---|---|
| 页面和交互 | `src/app/page.tsx` | 按钮是否可操作、错误是否显示、是否有静态假数据 |
| 视觉样式 | `src/app/globals.css` | 移动端布局、状态颜色、禁用状态 |
| 登录和数据通信 | `src/lib/supabase/client.ts` | 是否携带用户令牌、错误翻译、是否泄露密钥 |
| 数据库 | `supabase/migrations/*.sql` | 表约束、RLS、事务、执行权限 |
| 配置 | `.env.example`、Vercel 环境变量 | 公开变量和秘密变量是否分开 |

## 3. 功能审核清单

### 账户

- [ ] 用户名少于 3 个字符时拒绝注册。
- [ ] 密码少于 8 位时显示中文错误。
- [ ] 注册后可以直接登录（邮箱验证关闭期间）。
- [ ] 退出后不能查看账户、下单和持仓。

### 下单

- [ ] 金额低于 1 FW 时失败。
- [ ] 金额大于余额时失败且余额不变。
- [ ] 成功后余额减少。
- [ ] 成功后持仓页出现对应方向和份额。
- [ ] 刷新浏览器后持仓仍存在。

### 持仓

- [ ] “持仓中”和“已结算”可以切换。
- [ ] 无数据时显示空状态而不是假数据。
- [ ] 不同账户不能看到彼此持仓。

## 4. 数据库审核原则

- 所有数据库更改必须新增迁移文件，不能只在控制台手工修改而不留记录。
- 用户写操作优先放在数据库事务函数中。
- `security definer` 函数必须限制执行角色，并在函数内部检查 `auth.uid()`。
- 新表默认考虑启用 RLS。
- 金额字段使用 `numeric`，不能使用可能产生浮点误差的 `float`。

## 5. 发布审核

- TypeScript 检查必须通过。
- GitHub 更新目标必须是 `dark3779248-web/ycsc`。
- Vercel 项目根目录保持 `finwise-app`。
- 生产地址为 `https://ycsc-chi.vercel.app/`。
- 修改线上配置后，在变更记录中写明手工操作。
