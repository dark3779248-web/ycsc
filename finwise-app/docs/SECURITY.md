# 安全说明

## 已实施

- 密码交由 Supabase Auth 处理，应用不保存明文密码。
- 用户数据表启用 RLS。
- 订单、持仓、账本和通知只允许所属用户读取。
- 下单通过原子数据库事务执行。
- 只有 `authenticated` 角色能调用下单函数。
- `.env.local` 已被 `.gitignore` 排除。
- 浏览器只使用 Supabase Publishable Key；该密钥设计为可公开，真正权限由用户令牌与 RLS 决定。

## 当前临时设置

- 邮箱确认已临时关闭，方便开发测试。
- 重新正式邀请用户前应重新开启邮箱确认。
- Supabase 内置邮件服务仅适合测试；正式使用需要自定义 SMTP。

## 不得执行

- 不得把 Supabase Secret/Service Role Key 放入前端或 GitHub。
- 不得在浏览器直接修改余额。
- 不得把真实充值地址、私钥或助记词写入项目。
- 不得在没有合规评估的情况下开放真实资金交易。

## 上线前必须补充

- CAPTCHA、登录防爆破和设备风控。
- 管理员单独认证、角色检查和操作审计。
- 自动备份与恢复演练。
- 市场创建、结果确认和结算的双人审核。
- KYC/AML 与当地法律意见。
